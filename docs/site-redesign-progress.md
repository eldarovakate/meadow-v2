## 3. Архитектурные решения

- **`card_variant` для переиспользуемых инклюдов.** `product_card.html`/`product_carousel.html` используются каталогом, избранным, корзиной и главной. Любая новая визуальная ветка для главной идёт через `{% if card_variant == 'homepage' %}`, дефолтная ветка (без параметра) остаётся байт-в-байт прежней. Прежде чем что-то менять в этих файлах — сверяться, что каталог не задет (`grep`, потом визуальная/HTML-diff проверка `/catalog/`).
- **CSS-скоуп.** Все новые секционные стили — `.home-page .<section-name>*`. Карточные модификаторы — `.product-card.product-card--editorial` (составной селектор, не одиночный класс — иначе проигрывает по порядку в каскаде глобальному `.product-card`). Общие токены/классы (`.container`, `.section-title`, `.btn`, `.richtext`, `.product-card` база) не редактируются — только расширяются через более специфичные селекторы.
- **Перед удалением/переиспользованием CSS-класса — обязательно `grep` по всему проекту.** Дважды была найдена коллизия: (1) мёртвый CSS `.hero__inner/__content/__image-wrap` ожил и сломал новый Hero, когда переиспользовали имя `.hero__content`; (2) `.about__*` пришлось проверить на предмет пересечения с `.about-story__*` страницы `/about/` (это разные namespace, не пересекаются, но проверка обязательна).
- **StreamField: новые типы блоков добавлять в конец списка** в Python (`HomePage.body = StreamField([...])`), не переставляя существующие — порядок в списке влияет только на порядок в меню «добавить блок» в админке, а не на порядок уже сохранённого контента.
- **Миграции.** Django создаёт `AlterField` на `HomePage.body` при любом изменении структуры блоков (новое поле, новый тип блока) — это чисто state-tracking, реальных данных не трогает (StreamField хранится как один JSON-столбец). Правило: генерировать через `makemigrations`, **читать содержимое** перед `migrate` (убедиться — только `AlterField`, без `RunPython`/`RunSQL`), никогда не писать data migration вручную для контента — контент правится через ORM-скрипт в dev или через саму Wagtail admin.
- **`cta_url`-поля — `CharBlock`, не `URLBlock`.** `URLValidator` внутри `URLBlock` отклоняет относительные пути. Там где нужна валидация (Hero) — кастомный `clean()` с regex, разрешающим `/path/`, `#anchor`, `http(s)://...`.
- **Dev-контент.** Тексты/картинки блоков на dev правятся напрямую через ORM (`HomePage.body.raw_data` → модификация → `hp.save()`), чтобы можно было отрендерить и проверить в браузере до похода в production Wagtail. После каждой такой правки — точный список полей и значений идёт в отчёт, чтобы повторить в production вручную.
- **Тестирование верстки.** Встроенная панель «Браузер» в этой среде никогда не была реально открыта пользователем → скриншоты не работают, и что важнее — программный ресайз через неё не всегда генерирует настоящие `resize`/`matchMedia change` события (похоже, из-за отсутствия композитинга). Поэтому: (а) все проверки размеров/overflow идут через `getBoundingClientRect`/`getComputedStyle` в JS, а не визуально; (б) там, где логика зависит от resize-события (мобильное меню), добавлена CSS-страховка, не зависящая от JS вообще.

## 4. Правила бренда Meadow Shore

- **Язык.** Весь пользовательский контент — русский. Никаких английских декоративных подписей: `SHOP`, `EXPLORE`, `COLLECTION`, `FIELD NOTES`, `OUR STORY`, `NEW DROP`, `COLLECTION STORY`, `FOREST DWELLERS`, `ABOUT COLLECTION`, `FIELD NOTE(S)`, `NATURE NOTE`, `OBSERVATION`, `ARCHIVE ENTRY`, `КОЛЛЕКЦИЯ 01` (как публичное название коллекции — только как часть Hero-eyebrow, не как заголовок других секций). Название бренда `Meadow Shore` остаётся на английском — это ок.
- **Название коллекции.** Единственное публичное имя первой коллекции — **«Лесные жители»**. Внутри Python/технических имён допустимы английские идентификаторы (`ObservationSectionBlock` и т.п.) — это не пользовательский контент.
- **Характер.** Современно, взросло, спокойно, editorial, тактильно, слегка архивно, живо, лаконично, не идеально симметрично. **Не** cottagecore, не eco-shop, не outdoor-магазин, не сувенирная лавка, не «уютный магазинчик с милыми зверями», не generic beige minimalism.
- **Природа — не декор.** Meadow Shore не украшает вещи животными — центр мира бренда это наблюдение за конкретным местом/животным/деталью, из которого потом рождается принт или вышивка. Это прямо формирует систему «Наблюдений» (см. HOME-0X выше).
- **Дизайн-система.** Cormorant Garamond (заголовки) + Inter (текст/служебные подписи). Токены: `--color-ivory #f8f5ef`, `--color-beige #ede8df`, `--color-terracotta #b5614a`, `--color-moss #4a5e3a`, `--color-forest #2d3d25`, `--color-brown #3d2e22`, `--color-brown-dark #2a1f16`, `--color-stone`. Новых HEX не вводить без крайней необходимости — всегда сначала искать подходящий существующий токен.
- **Terracotta — только акцент.** Hover-состояния, мелкие детали. Не заливать им большие кнопки/блоки повсеместно.
- **Фоновый ритм секций.** Ivory → Beige → Forest → Brown (уже используется: featured-products=Ivory, collection-story=Beige, observation=Forest).
- **Коммерция vs. история.** Секции ниже Hero и товаров — не e-commerce. Никаких discount-badge, процентов скидки, «Добавить в корзину», «Смотреть товар», «Подробнее» и подобных CTA внутри editorial-блоков (`О коллекции`, `Наблюдение`). CTA уместен только там, где он реально нужен (Hero, заголовок секции товаров).

## 8. Важные технические находки

- **`URLBlock` отклоняет относительные пути.** Любое поле cta-ссылки, которое должно принимать `/catalog/`, должно быть `CharBlock` (+ свой валидатор при необходимости), не `URLBlock`.
- **Специфичность CSS-модификаторов.** Одиночный класс-модификатор (`.product-card--editorial`) имеет ту же specificity, что и переопределяемый базовый класс (`.product-card`) — если базовое правило идёт позже в файле, оно выигрывает. Нужен составной селектор: `.product-card.product-card--editorial`.
- **Grid-проценты в `minmax(Xpx, Y%)`** резолвятся не всегда интуитивно относительно companion-трека `1fr` — итоговый визуальный %-сплит колонок стоит всегда перепроверять живым замером (`getBoundingClientRect`), а не доверять голой арифметике.
- **Мёртвый CSS может «ожить».** `.hero__inner/__content/__image-wrap` — остатки старой версии Hero, не использовались нигде в шаблонах, но при введении нового класса с тем же именем (`.hero__content`) снова начали действовать и сломали раскладку. Правило: `grep` перед использованием ЛЮБОГО имени класса, даже кажущегося новым.
- **Header-баг 768–903px** — переключение на desktop-раскладку слишком рано (768px) плюс избыточный `padding-right: 6rem` у nav. Порог сдвинут на 1024px, padding уменьшен до `2rem`.
- **Мобильное меню, зависающее на desktop-ресайзе** — самая надёжная защита оказалась чисто CSS (`display:none` при `min-width:1024px`), не зависящая от того, сработает ли JS-событие. JS-сброс состояния (aria/scroll-lock) продублирован через `matchMedia('change')` **и** `window.resize` одновременно.
- **Тестовая среда:** встроенная панель «Браузер» в этой сессии ни разу не была открыта пользователем → она не композитит кадры. Следствия: скриншоты недоступны; `getComputedStyle` для CSS-transition-анимируемых свойств (`transform`), `requestAnimationFrame` и `:focus-visible`/`:focus` могут давать недостоверный результат в этой конкретной вкладке, хотя DOM-состояние (classList/атрибуты/`activeElement`) обновляется корректно; программный resize через неё не всегда шлёт настоящие `resize`/`matchMedia change` события. Реальный Chrome (через отдельный browser-инструмент) использовался как второй канал проверки, но без возможности программного ресайза окна.
- **Проверка Wagtail admin без пароля владелицы.** Для подтверждения, что новый тип блока (`observation`) корректно регистрируется и доступен в StreamField-редакторе, использовался `django.test.Client.force_login()` на найденном dev-суперюзере — не логин в реальный аккаунт, стандартный безопасный способ протестировать admin-вьюху в dev-окружении.
